# Codebase Map
## Areas
- `aidd_docs/INSTALL.md` holds the target folder structure: one package per bounded context, each split into domain, application and infrastructure.
- `aidd_docs/memory/external/drlibre-specs.md` is the functional specification the code implements.
- `src/drlibre/shared_kernel/`: `Id`, `Clock` port, `Result`, `ErrorCode` (spec 4), `DomainError`, `UnitOfWork` port, `Page`/`PageRequest` (20 rows), `FieldErrors`, `Dependents` (`has_dependents` lists) and `Week` (a hospital-zone week within the slot horizon, shared by scheduling and search).
- `src/drlibre/audit/`: write side of the audit log; `AuditEntry` refuses personal metadata, `DjangoAuditLog` (append-only), `DjangoUnitOfWork` (`transaction.atomic`); `AuditQueries` inbound port tells identity who acted and lists an entity's entries; `ViewAuditJournal` serves the admin journal.
- `src/drlibre/identity/`: users, password sign-in, sessions (token hash), lockout (Redis), password change, user management, `authorize_owned` guard; `StaffLookup` inbound port for other contexts.
- `src/drlibre/organisation/`: hospitals, specialties, departments, rooms, appointment types, clinician profiles; `DjangoReferenceQueries` reads; `SchedulingSlotRefresh` and `ScheduleAndBookingDependents` reach scheduling through its ports.
- `src/drlibre/health/`: health check context; `DatabaseProbe` port, PostgreSQL adapter, `SystemClock`.
- `src/drlibre/scheduling/`: availability rules, time off, pure `SlotEngine`; `scheduling_slot` table rebuilt by `RefreshSlots`, read by `FindFreeSlots` and `FindFreeWeek` (reschedule week); `NextBookableSlots` for refused bookings, `IsSlotFree` and `FreeCliniciansAt` for booking; `ExtendSlotHorizon` daily job; appointments and holds come from booking through `BookingClinicianAppointments` and `BookingSlotHolds`.
- `src/drlibre/booking/`: appointments, booking holds, verification codes, booking rules, round robin and placement; patient and clinician cancel and reschedule, clinician status changes, clinical notes and `BookForPatient`, reminders; waitlist (`WaitlistEntry`, join, automatic and manual offer, accept, expiry), read by `SqlWaitlistQueries`; `BookingOptionQueries` (`SqlBookingOptionQueries`) lists the type, clinician and room picklists of the booking and waitlist forms; `SqlPatientAgenda` and `SqlClinicianAgenda` read the patient's and clinician's appointments, `AuditAppointmentHistory` the audit trail; `OutboxBookingNotices` notifies in-app and by email.
- `src/drlibre/reporting/`: read-only dashboard (§13): `ActivityQueries` in SQL, pure `available_minutes`.
- `src/drlibre/interop/`: FHIR read side, `Sql*` queries scoped by `Reader`, `SqlReaders` resolving it, `DjangoConditionalWrites` (`If-Match`); imports no context.
- `src/drlibre/search/`: read side, `SqlSearchQueries` (providers, hospitals, specialties, provider, hospital and specialty pages).
- `src/drlibre/notifications/`: `Mailer` port and its SMTP adapter, `CeleryEmailOutbox`; in-app `Notification` with `DjangoNotifications`.
- `src/drlibre/persistence/`: `TrackedRecord` (spec §3 `created_at`, `updated_at`, `created_by`) for infrastructure models, creator set by `act_as`, which interfaces reach through `drlibre.bootstrap`; imports no context.
- `src/drlibre/interfaces/`: driving adapters; `api/` mounts Django Ninja at `/api/v1` (health, auth and sign-in link, search, public pages, booking holds, `GET`/`POST /appointments` (patient or clinician), cancel, reschedule, check-in, complete, no-show, `POST /waitlist`, `POST /waitlist/{id}/accept`, `GET /slots`, `POST /jobs/reminders`), `web/` holds search, booking, public pages and the patient portal under `/portal/` (appointments, cancel, reschedule, `.ics`, notifications, profile, waitlist), views, presenters and templates (sign-in, role areas, admin console: dashboard (`console/dashboard.html`), appointments list, CSV export, file and book wizard (`/console/appointments/`), audit log (`/console/audit/`), settings and reminders (`/console/settings/`), clinician weekly summary, read-only week calendar and waitlist (`/console/waitlist/`), clinician workspace under `/workspace/`: today, calendar, appointment file with notes and history, patients, rooms, availability and time off), `fhir/` is the FHIR R4 facade at `/fhir` (registry, metadata, `narrative` (generated `text`), routers, mappers, schemas, `OperationOutcome`), `jobs/` holds Celery tasks (hold expiry, waitlist expiry, reminders, slot horizon).
- `src/drlibre/bootstrap/container.py`: the composition root; `use_container` swaps in fakes for tests.
- `config/`: settings from `.env` via pydantic-settings, urls, Celery app and beat schedule, correlation id middleware, structlog JSON logging.
- `loadtests/locustfile.py`: Locust `Visitor` (search, booking), `Patient` (portal, by Mailpit link), `Clinician` (workspace), `Admin` (console, export, audit) and the API list per role; codes and links read from Mailpit.
- `tests/`: `features/` Gherkin (one file per Story), `use_cases/` pytest-bdd on fakes (`fakes/world.py` wires them), `contracts/` fake vs real, `fhir/` FHIR R4 contract tests (steps for `features/fhir/`, Epic journey on the demo seed), `presenters/` ViewModels, `api/` and `integration/` against compose services, `e2e/` Playwright journeys with vendored axe-core, helpers in `pages.py` (`read_mail(to, subject)`, `clear_mail`); `E2E_BASE_URL`, `E2E_MAILPIT_URL`, `E2E_REDIS_URL` target another stack.
- `docker/`, `docker-compose.yml`: image, entrypoint (migrate, seed, gunicorn) and the six-service stack.
- `.github/workflows/ci.yml`: CI, pre-commit gates, pytest against PostgreSQL, Redis and Mailpit services, and `fhir-conformance` (HL7 validator on the seeded app).
- `scripts/fhir-validate.sh` with `scripts/fhir_samples.py`: samples every `/fhir` answer per reader and runs the pinned HL7 validator.
- `scripts/seed.py`: idempotent demo seed through the use cases (two hospitals, one sign-in per role plus a second clinician of HNORD-CARD, a passwordless patient, weekday rules for both clinicians, next-working-day appointments for the demo clinician, past-week appointments in every closed status and source, two waitlist entries, a staff-only type `HNORD-ECHO`), run with `python -m scripts.seed`; `--size load` adds 8 hospitals, 200 clinicians signing in with the demo password, 5k patients, 50k appointments with one audit entry each and a notification per future one, by bulk insert.
- `static/vendor/`: vendored HTMX 2.0.11 and Pico.css 2.1.1; `static/drlibre.css` holds the few own rules.
